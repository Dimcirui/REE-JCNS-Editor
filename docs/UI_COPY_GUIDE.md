# 界面文案规范

适用于用户在 Blender 里能看到的所有文字：属性的 `name` / `description`（悬停提示）、
面板里的 `label`、按钮文字、`self.report` 的提示、枚举项的名称和说明，以及
`modules/jcns_source_read.py` 里 `READ_MODES`、`target_rule`、`read_rule` 这类给面板用的说明表。

## 核心原则

**界面只写用户需要的结论。** 作用、生效条件、常用值、风险、当前状态、下一步操作都可以写；
研究依据、验证过程和开发历史放进 `docs/` 或 `scripts/probes/README.md`。

自检：一句话如果主要在回答"我们为什么这样认为"，它就不属于界面。

## 界面的六条原则

这是上面核心原则的展开，面板、按钮、报告都按它写：

1. **名字承载信息，能靠名字表达的不写说明。** 键Start / 键1 / 键End 本身就说明了起点、折点和终点，
   不再另写一句「键按读数排列」。
2. **只写用户读完能采取行动的话。** 警告 = 问题 + 动作，尽量直接带按钮，不写原因和原理：
   「预览正在驱动 4 根骨」后面跟「清除预览」，不写「记录的姿态会被预览改写」。
3. **默认视图不出现内部概念。** 三点映射、ComplexMapping、关键帧（N 个及以上）、`+25`、`bit0`、AttrFlags、
   字节偏移只出现在「高级」子面板和悬停提示里。`tools/ui_copy_check.py` 对面板代码里 `label` / `text=` 的字符串查这几个词。
4. **状态用图标或短词，不用句子。** 「已记录」是对勾图标；「已应用 3/12」是数字。
5. **同一概念只有一个名字、一个入口。** 目标骨称「被驱动」，源称「驱动」，不再混用驱动源、驱动骨、源骨骼；
   预览只有顶层「预览」一个入口；「烘焙约束」这个名字全局只用它。
6. **悬停提示最多一句，不解释引擎。**

典型改写：

> 「另有 N 条约束也在驱动…本条会被靠后的那条整条覆盖…用▲▼把它移到最后」
> →「与 [02] 共用通道，只有最后一条生效」+「合并」按钮

> 「X 局部 X 轴 -71° → -35°：…」逐段文字描述 → 删除，只留锚点折返、折点越界、静止偏移三种警告；曲线图和实时读数保留

> 分区横幅「就地写回版本只能改数值，不能增删……」→「v29 只能改数值，不能增删、换序或改骨骼名」+ 锁图标

## 悬停提示的结构

按顺序写，用不到的项跳过，合起来不超过一句话（用逗号或分号连接）：

1. 一句话说作用。字段名和标签已经表达的不重复。
2. 必要的生效条件。
3. 中性值、常用值或有效范围。
4. 必要的风险提示。
5. 含义确实未知时直接写：「具体作用未知。通常为 0。」或「可能影响……；具体换算关系未知。」

示例：

> 读取方式为「欧拉角」时的分解顺序，其他读取方式忽略它；常见值为 XYZ（约 82%）。

> 1 把值叠加在静止姿态上，0 替换所写的轴；对缩放不起作用。

## 禁止出现的内容

- **研究过程和出处**：原版语料、全语料、实测、实机、测试台、第 N 轮、样本、推测、尚未确认、待验证、置信度、日期。
  统计结论可以保留，来源要删。
  - 「在全部原版文件里恒为 (0,0,0,1)」→「固定为 (0,0,0,1)，请勿修改。」
  - 「原版 77% 的源用 3」→「最常用（约 77%）。」
- **开发历史**：原名、bt 叫作、曾被误读为、已改为、之前当作……。旧名和别名只记在 `docs/` 或代码注释里。
- **内部术语**：fallback、raw bytes、opaque、内部属性名（`attr_flags_other`、`input_type` 之类）、函数名、模块名。
  用户确实要认的格式名可以保留：`JCNS`、`ReadJointTable`、`ComplexMapping`、骨骼名。
- **调试信息**：traceback、异常类名、本地路径。这些用 `traceback.print_exc()` 打到控制台，
  界面只提示「详情请查看系统控制台」。
- **口号式或夸张的语气**：「预览在骗你」「不作数」「千万别碰」「静默无效」。
  改成准确的陈述，例如「此时预览的形状不代表游戏里的效果」。

## 写法要点

- **不确定写成功能状态，不写成验证状态。** 写「可能影响……」「具体作用未知」，不写「待验证」「未实测」。
  面板里用图标区分：已知的结论用 `CHECKMARK`，只是推断的用 `QUESTION`，文字本身不再写"实测 / 推断"。
- **错误和限制要能照着做。** 说清发生了什么、有什么影响、怎么处理。没有可靠办法就不编造建议。
- **状态要区分。** 暂不支持编辑、只读、没有数据、读取失败、尚未选择是不同的状态，不能统一写成「不支持」。
- **作用对象要明确。** 光秃秃的按钮由面板标题或同一行的标签交代对象：「预览」面板里的「应用」「清除」作用于整个文件，标着「仅选中的条目」的那一行只作用于选中的条目。
- **数字只留有操作价值的。** 常用值、默认值、范围、比例、固定值、风险值。样本规模（「1103 个文件」）不留。

## 语言

界面有中文和英文两种语言。所有文案放在 `modules/jcns_strings/`（按区域分文件，键以文件的前缀开头），
代码里用 `T("area.key")` 取，带数值的写成 `T("key", a, b)`（`%s` / `%d` 占位符）。两种语言的含义、确定程度、
占位符、数值和类型名必须一致；占位符的个数和顺序一致，`tools/i18n_check.py` 会查。

- 默认语言：没保存过选择时跟随 Blender 的界面语言（中文环境用中文，其余用英文）；面板顶部的
  [English][中文] 切换并记住选择。面板正文即时切换；属性名、悬停提示、枚举项和面板标题在注册时取值，
  切换后重载插件或重启 Blender 才生效。
- 不翻译写进场景或文件的名字（物体、集合、骨骼、驱动器名）、枚举标识符和给开发者看的 `print`。
- 新增文案：在对应的表里同时写 ZH 和 EN，不要在代码里留中文字面量；侧栏标签页名统一用 `common.category`，
  否则面板会被拆到两个标签页。

## 提交前检查

- 跑 `python tools/ui_copy_check.py`。它扫界面文案里的高风险词（实测、实机、验证、语料、样本、原版文件、
  推测、原名、bt、fallback、raw、日期、第 N 轮……），另外对面板默认视图里的内部词（见原则 3）和旧术语
  （驱动源、源骨骼、驱动骨）报错；「高级」面板（类名含 Advanced / Raw / Reserved）和带 `# ui-copy: advanced`
  的行除外。命中后逐条人工判断。
- 跑 `python tools/i18n_check.py`：键齐全、两种语言占位符一致、EN 里没有中文、代码里没有残留中文字面量。
- `git diff --check` 通过。
