# UI 框架

每个 section 的编辑方式都不同，所以框架只管三件事：**有哪些分区、能对它做什么、怎么在视口里看到效果**。
每个分区具体怎么编辑，留给它自己的编辑器面板。

## 面板树

侧栏（3D 视图 → 侧栏 → 标签页「JCNS 编辑器」）按「先建约束、再看效果、最后细改」排成五个顶层面板：

| bl_order | idname | 标题 | 内容 |
|---|---|---|---|
| 0 | `JCNS_PT_status` | MHWs JCNS | 新建（下拉选游戏）/导入/导出、工作集合、骨架、文件名与版本（版本不在已验证列表里才出警告）。没有 JCNS 文件时只剩一行导入提示 |
| 1 | `JCNS_PT_sdk` | 烘焙约束 | 摆姿势记录键，生成 Outputs 约束；对话框里「生成后预览」默认开（`jcns_sdk_ops.py`） |
| 2 | `JCNS_PT_preview` | 预览 | 整个界面唯一的预览入口：整个文件应用/清除，另一行只处理选中的条目；显示已应用数量 |
| 3 | `JCNS_PT_edit` | 编辑 | 分区标签、条目列表（Outputs 可切到按骨骼分组）、增删换序；选中条目的详情是它的子面板 |
| 4 | `JCNS_PT_file_info` | 文件信息 | ObjectSettings、ConeDriver 表、读取骨表的数量，默认折叠 |

没有 JCNS 根节点时，除「MHWs JCNS」外都不出现。

「编辑」下的子面板（`jcns_editors.py`），只在选中条目是该类型时出现：

    编辑
    ├─ 被驱动 · 驱动 · 映射曲线 · ConeDriver 输入（文件有 ConeInput 才出现）· 工具（镜像、合并所有同通道约束）· 高级（折叠）   Outputs
    ├─ Multi 蒙皮  └─ 高级（折叠）
    ├─ Aim 瞄准   └─ 高级（折叠）
    ├─ RotExpr 旋转表达式  └─ 高级（折叠）
    ├─ Material 材质  └─ 原始字段
    ├─ JXG 导出图
    └─ 未知类型

「高级」放引擎规则说明（✓ 已知，? 推断）、含义未知的字段和取值固定的字段；默认视图里不出现
三点映射、ComplexMapping、`+25`、bit0、AttrFlags、字节偏移这类内部词（`tools/ui_copy_check.py` 会查）。

## 分层

| 层 | 文件 | 内容 | 能否离线测 |
|---|---|---|---|
| 事实 | `modules/jcns_kinds.py` | `KINDS`（图标、是否有序、能否新建、用哪个预览后端）和 `capabilities(kind, FileState)`（能否编辑/增/删/换序 + 原因） | `tests/test_kinds.py` |
| 预览规划 | `modules/jcns_preview_plan.py` | Multi/Aim/RotExpr → 描述一个原生骨骼约束的 `ConstraintPlan`（含 warnings） | 同上 |
| 预览实现 | `jcns_preview.py` | `PreviewBackend` 接口、`DriverBackend`（Outputs）、`ConstraintBackend`、通用的 `jcns.preview_apply/clear` | `tests/test_bpy_ui.py` |
| 框架 UI | `jcns_ui.py`、`jcns_sdk_ops.py` | 状态、预览、编辑（分区标签 + 条目列表 + ＋－▲▼，或按骨骼分组）、文件信息、烘焙约束 | 同上 |
| 各分区编辑器 | `jcns_editors.py` | 每种类型一组面板，只在当前条目是该类型时出现 | 同上 |

条目仍然是 Empty，`constraint_type` 存类型。列表的数据是 `Collection.objects`（`template_list` 要真正的 RNA 集合；
`Object.children` 是 Python 元组），`rp.entry_index` 用 get/set 读写活动物体，所以列表、视口、大纲三处自动同步，不需要 handler。
标签页 `rp.browser_kind` 只是过滤器，用 `prop_enum` 逐个画：只画 Outputs 和有条目的分区（当前分区总是画），没有条目的可新建分区另有一个「＋」按钮；
选中别的分区的条目时，「编辑」给一个"切到该分区"的按钮。`rp.browser_view`（按条目/按骨骼）只在 Outputs 分区出现，
按骨骼就是按被驱动的骨骼分组列出通道和上面的条目，带「合并所有同通道约束」。

## 谁说了算

`capabilities()` 是唯一的规则来源：面板灰掉某个按钮，和对应 operator 的 poll / execute 用的是同一个函数
（`jcns_operators._caps_for`）。以前这些规则散在 `_sections_editable`、`_draw_version_note`、`_skin_table_locked`
和各 operator 里。

| | 重建版本（v35/v102） | 就地版本（v22/v29…） |
|---|---|---|
| Outputs | 全部可以 | 只能改数值：不能增删、换序、改骨骼名 |
| Multi / Aim / RotExpr | 可编辑，可增删，**不换序**（顺序含义未证实）；Multi/Aim 带读取骨表且没设骨架、RotExpr 映射非单一常量时不能增删 | 全部锁定，导出原样保留 |
| Material | 可编辑、可删，不能新建 | 只能改哈希/变换 ID |
| JXG | 可编辑、可删，不能新建 | 锁定 |

## 预览（"驱动器"的推广）

Outputs 的驱动器就是一种预览：按下"应用"，视口里的骨架动起来。其余分区只要能说成"这根骨跟着那根骨"，
就能用 Blender 原生骨骼约束表达。入口只有顶层「预览」面板（整个文件，或 `scope='ENTRY'` 只处理选中的条目），
各编辑器里没有预览按钮；Multi/Aim/RotExpr 的预览只是对照用，面板在文件里有这类条目时给一行「仅供参考」。
烘焙约束生成后默认对生成的通道应用预览（`jcns_sdk_ops.preview_channels`，失败只在报告里说一句）。两者走同一套接口：

    Kind.preview → BACKENDS[id] → units（一组必须一起应用的条目） → apply / clear / refresh

- **unit**：Outputs 是同一 (骨骼, 变换, 轴) 通道上的所有约束（Blender 一个通道一个驱动器，且只有最后一条生效）；其余是单条。
- Outputs 驱动器按实测的引擎行为读源骨（2026-09-30，测试台第 6–8 轮）：目标旋转固定按 XYZ 欧拉合成（引擎是 静止·Rz·Ry·Rx，与文件里各轴的先后无关）。源骨读的是相对父骨的**完整**变换，静止姿态和静止偏移都算在内，`+25`（读取方式 InputType，源面板里的枚举）决定怎么分解：0 = 位置分量，1 = 欧拉分量（顺序由 +27 欧拉顺序决定），2 = 缩放，3 = 绕 X 的摆动-扭转（q = 摆动·扭转；X 取扭转角，Y/Z 取 2·atan2(s_轴, s_w)），4 = 同上但 q = 扭转·摆动，5 = 旋转向量分量；3/4/5 在源的参考系四元数（原 ref_frame）里分解。驱动器取源骨三个通道，`jcns_ch` 重建完整变换后按 `modules/jcns_source_read.py` 分解。条目按文件顺序求值，所以源骨的某个通道如果由本条或后面的条目驱动，就读静止值。目标旋转按变换类型合成（第 9 轮实测，与源读取方式一一对应）：1 = XYZ 欧拉，4 = 摆动·扭转，5 = 扭转·摆动，6 = 旋转向量，13/14 = 每根骨一个绕所写轴的旋转、骨上最后一条 13/14 胜出；非欧拉类型的骨头整骨成组预览。目标条目 AttrFlags bit0 为 1 时值叠在静止姿态上，为 0 时替换：欧拉类型换掉静止欧拉里所写的轴，4/5/6 把静止姿态按该类型自己的分解取出、换掉所写的轴、其余保留（第 13 轮实测），13/14 丢掉整个静止旋转。同一根骨上混用旋转类型时，整骨按**最后一条**的类型合成，所有条目的值都参与（类型 4 条目的 Y 值当欧拉 Y 用；第 13 轮 (1,4,1)、第 15 轮五种排列都是最后一条决定，第一条和多数都被排除）。源的插值字节 +28 决定每段怎么过渡（第 15、16 轮实测，三点映射也是每段）：0 线性、1 缓入 t³、2 缓出 1−(1−t)³、3 缓入缓出 3t²−2t³。bit0 混用时（有的通道叠加、有的替换），先把叠加通道合成的旋转叠在静止姿态上 q1 = 静止·合成(叠加)，再把 q1 按该类型自己的分解取出、换掉替换通道的分量、重新合成（类型 1、4、5、6 都吻合，第 16 轮）。OutputData 的 +72、+74、+75 在旋转、平移、缩放上都没有效果，同一根骨上混用平移和旋转时 +75 取 2 或 8 也没有差别（第 15、16 轮）。UnknownFloat2 在旋转类型 1 上没有效果。静止旋转为单位的骨头两者没有区别；静止旋转非单位、又有 bit0=0 旋转通道的骨头，三个 rotation_euler 驱动器作为一组生成，每个都按整根骨求值（静止姿态的欧拉角里换掉被替换的通道，再叠上叠加通道），第 11 轮已验证多轴静止欧拉 (-2°,17°,-23°) 的逐轴替换（旋转误差 ≤0.001026°）。平移值写在父骨自己的局部框架里，父骨有静止缩放时世界偏移按它逐轴放大（第 18 轮实测），所以预览把平移增量乘父骨的静止缩放；负缩放的父骨不支持。平移 bit0 已实测（第 10 轮）：1 在父骨轴上叠加静止位置，0 只替换所写轴，未写轴保留静止偏移；预览用三个 location 驱动器一起把父骨轴增量换回 Blender 的静止局部基底，编辑、缓存重建和清除都整组处理。第 11 轮非单位静止缩放 (1.4,0.7,1.8) 下，bit0=0/1 都直接替换所写轴，未写轴保留静止值，乘法候选已排除。Blender 骨骼没有静止缩放（网格就绑定在静止姿态上，pose 缩放 1 就是静止缩放），所以缩放目标驱动 pose 缩放 = 引擎值 ÷ 静止缩放（静止缩放取自 RE Mesh Editor 保存的原始局部矩阵），缩放源读取 pose 缩放 × 静止缩放；导入不改 pose，清除缩放预览恢复为 1。引擎的处理规则在 Outputs「高级」里列出（✓ 已知，? 推断）。13/14 的 F49 单 Y 旋转与 F17 三轴平移、缩放共存，旋转条目放前或后结果相同；其他 AttrFlags、负缩放、剪切及非单位缩放源读取仍未实测。驱动器直接使用表达式结果，移除默认 identity 键，避免接近 0/1 的小值被 F-Curve 吸附。
- 状态存在条目上的 `preview_on`（`preview_bone` 记录约束现在挂在哪根骨上，改了目标骨能清理旧的）。
- 编辑属性时 `update` 回调调 `jcns_preview.refresh()`；预览已开则跟着刷新，没开则零开销。改到没有有效预览的状态（例如瞄准轴变成斜的）会撤掉旧约束。

| 分区 | 后端 | 对应 | 置信度 |
|---|---|---|---|
| Outputs | driver | 目标骨通道上的脚本驱动器（已实机验证） | 实测 |
| Multi | constraint | `ARMATURE` 约束，各源骨按权重除以权重和后混合（第 12 轮实测：位置是矩阵线性混合，旋转是归一化四元数和；Blender 的旋转是矩阵和，略有差别） | 位置实测，旋转近似 |
| Aim | constraint | `DAMPED_TRACK`，轴取 Vec1（必须是坐标轴，否则拒绝）；up 骨和其余向量不参与。只有类型 4 与引擎一致（从静止姿态最短弧）；类型 0–3 引擎还固定翻滚，类型 5 丢掉静止姿态，旋转偏移和影响≠1 预览都不做 | 类型 4 实测，其余未预览 |
| RotExpr | constraint | `TRANSFORM` 约束，局部旋转→旋转，每轴 ×系数（`rot_floats`），REPLACE。引擎：系数 (1,1,1) 是精确拷贝；其他系数小角度时每轴 ×系数，大角度偏离，单轴结果是绕该轴的纯旋转但角度公式未定；字节[1]=0 替换静止姿态，=48 时 静止·结果 | 拷贝实测，其余近似 |
| Material / JXG | 无 | Blender 里没有对应物 | — |

这些预览是**拿来对照游戏的假设**，不是结论。已知疑点：Armature 约束对有父骨的骨骼可能把父级运动算两遍；
Transformation 约束按欧拉分量乘系数，引擎是否如此未测；预览约束和 Outputs 驱动器同时作用在同一根骨上时叠加方式与引擎不一定一致。

## 新增一种分区 / 预览

1. `modules/jcns_kinds.py`：加一条 `Kind`，在 `capabilities()` 里写规则，跑 `tests/test_kinds.py`。
2. `jcns_editors.py`：继承 `_EditorMain` 写主面板（自动挂在「编辑」下），原始字段和引擎规则说明放进一个叫「高级」的 `_Sub` 子面板（默认折叠），加进 `_classes`（父在前）。
   面板开头调 `_begin()`，它按 `capabilities` 决定整块能否编辑并画出原因。不要在编辑器里画预览按钮。
3. 要预览：复用 `constraint` 后端（在 `modules/jcns_preview_plan.py` 加一个 `plan_*`，在 `jcns_preview._plan_for` 接上），
   或者写新的 `PreviewBackend` 注册进 `BACKENDS`。
4. `jcns_ui.JCNS_UL_Entries.draw_item` 里想给行加状态图标就在那里加。
5. `tests/test_bpy_ui.py` 用带该类型条目的样本再跑一遍。

## 待讨论：各分区的编辑器怎么做

每个分区的编辑器把已知含义的字段放在主面板（Outputs 的叠加开关、折点映射、参考系；Aim 的类型与向量；RotExpr 的系数与静止姿态模式），含义未知和取值固定的字段在「高级」子面板。
下面这些是搬完之后值得重新设计的地方，按分区列出：

- **Outputs**：映射方式二选一显示（已做：有 ComplexMapping 的源在「映射曲线」里显示关键帧曲线，曲线本身是约束 Empty 上的
  F-Curve，在曲线编辑器里编辑，见 jcns_cm.py）；列表行应显示"被后面覆盖"（已做）和"静止时已偏转"；多源约束的编辑流程。
- **Multi**：源数超过 4 的提示；权重和≠1 引擎会归一化（第 12 轮实测），编辑器里只提示。
- **Aim**：`WorldUpType` 决定 up 骨和 `vec0` 是否有意义（1/2 必带 up 骨，0/3/4/5 从不带，`vec0` 只在 2 非零），
  已放进主面板，辅助骨和上方向向量按类型置灰。第 12、14 轮实测：Vec1 是本地瞄准轴，Vec2 是本地对齐上方向的轴；
  类型 0 上方向取世界 +Y（Vec3 无效），3 取 Vec3 给出的世界方向，1 取 up 骨位置方向，2 取 up 骨的一根局部轴（Vec3 选：(0,1,0) 是 Y，(0,0,1) 是 Z），
  4 从静止姿态最短弧，5 从父骨朝向最短弧（丢掉静止姿态）。Vec0 是 XYZ 欧拉偏移（弧度），右乘在瞄准结果后面（第 17 轮）；影响≠1 时引擎结果退化（类型 0 世界旋转几乎不动），预览按影响直接混合。
- **RotExpr**：系数（`rot_gains`）和静止姿态模式（`rot_rest_mode`）已放进主面板；`rot_rotation`/`rot_scale` 是恒等四元数，
  `rot_scale` 这个名字有误导性。
- **Material**：哈希编辑对人不友好；项目里有 `hashUTF16`，可以做"输入名称→算哈希"（未确认材质名哈希用的是同一个函数）。
- **文件信息**：ObjectSettings、ConeDriver 表、读取骨表目前只读展示；ObjectSettings 的含义还没研究过。
